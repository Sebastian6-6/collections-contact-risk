# Documents and the repository map

## Ingest

The user drops originals (PDF, DOCX, PPTX, XLSX, HTML, CSV, images, MD, TXT)
into `.context/raw/`, subfolders allowed. `ctx.py ingest` converts only what is
new or changed (hash-based), writes `.context/converted/<id>.md` with
`<!-- page N -->` markers (slides and sheets count as pages) and regenerates
`index.md`. `/c` runs this check every time; when it reports pending documents,
run the ingest it asks for.

- Long batches: 600000 ms timeout; more than ~20 files, run in the background and
  report when done. Another session already ingesting: wait.
- `--force <id|file>` reconverts one document.
- `ctx.py forget <id>` drops a document: manifest entry, converted Markdown and
  index row. It leaves `raw/` alone; delete or replace the original first, or it
  is converted again on the next ingest. Use it when a document is withdrawn or
  must be replaced by a sanitized version.
- Legacy `.doc/.ppt/.xls` are not supported: ask the user to save them as
  `.docx/.pptx/.xlsx`. Office lock files (`~$…`) are ignored.
- Failures are listed with the reason and shown in `index.md`; the rest of the
  batch still converts.

## After converting: summaries and tags

For each document marked `_pending summary_` in `index.md`, read only the first
~150 lines of its converted file (front matter + opening pages) and run:

```
ctx.py doc <id> --summary "One English sentence: what it is and what it covers." --tags "churn,crm,rules"
```

If the user said where an original came from (Drive folder, system, e-mail),
record it: `--origin "Drive / Specs / CRM"`. Raw files are not versioned, so the
origin is how the original is found again on another machine.

## Images

Photos and diagrams with little text are flagged `needs_description`. Open the
original in `.context/raw/` (you can view images), write 3–8 English sentences
describing what it shows (structure, labels, relationships, numbers) to a temp
file, then `ctx.py doc <id> --description-file <tmp.md>`. Done once, it saves
viewing the image again later.

## Reading documents

Check `index.md` first, open only the relevant converted file, and jump to pages
via the markers. Prefer the converted Markdown over originals. Record what you
used under `## Documents in use` in the topic's STATE.md with page ranges.

## Map

`MAP.md` is regenerated by every `/c` from file names and sizes only: partitioned
files collapse into patterns (`sales_*.csv (20250101 → 20251231)`), CSV headers
come from the first line, Parquet rows/columns appear when `pyarrow` exists.

- Folders without purpose are listed in a TODO: infer a short English purpose
  from folder and file names only (do not open files) and run
  `ctx.py describe <folder> "<purpose>"`. Correct it when the user describes a
  folder differently.
- Before opening a data file, check its row in the map; often the columns are
  enough. When you need the data: slice it (`head`, Read with a limit) or use the
  query tool the project names in PROJECT.md → Data sources (a warehouse CLI,
  DuckDB, pandas). The skill does not connect to warehouses. When the user tells
  you where data lives, record it with `ctx.py project "Data sources" --file
  <tmp.md>` (pointers only, never credentials).
